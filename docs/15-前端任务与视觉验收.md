# 15 前端任务拆分、页面Prompt与视觉验收

执行对象：前端协调者、页面实现Agent、浏览器验证Agent。16个页面/骨架任务见 `tasks/frontend-tasks.json`，任务Prompt见 `prompts/frontend/`；它们是48核心包的子任务映射，不额外制造第13个版本。F00是共享底座、F02/F07包含覆盖路由的弹层，其余是独立页面。发布前全部需要集成。

## 1. 前端目录与唯一owner

```text
frontend/src/
  app/                 # 路由、providers、error boundary；F00 owner
  shared/
    ui/                # shadcn受控基础组件；F00 owner
    layout/            # AppShell/PageHeader；F00 owner
    styles/            # tokens/theme/typography；F00 owner
    api/               # HTTP/CSRF/error/SSE封装；F00 owner
    query/             # query key工厂、统一失效辅助；F00 owner
    generated/         # 契约生成，只由C执行生成
    lib/               # 纯函数，新增公共能力先审查
  features/
    library/ capture/ reader/ jobs/ search/ agent/ approvals/
    memory/ cards/ review/ settings/ backups/ trash/ auth/ organization/
      api/             # feature typed adapter/query options，不能另造HTTP client
      components/      # feature内部组合
      pages/           # 路由组合与状态边界
      model/           # 纯UI派生/局部状态，非后端业务规则副本
      tests/           # 组件与feature行为测试
  mocks/               # 冻结契约fixture与MSW handler，不进生产成功路径
frontend/e2e/          # 浏览器场景，按pageId和跨页flow分组
frontend/visual/       # 截图用例配置/受审查baseline
```

feature只能导入shared和本feature。跨feature组合经app层或明确公共契约协调，不形成双向导入。reader使用CitationLink，agent也使用它；不能各自实现引用URL格式。组件不能直接fetch；feature api通过shared api，React Query keys包含owner/session、filters、revision等实际影响结果的维度。logout清除旧owner缓存。

## 2. 批次与前后关系

| 批次 | 前端任务 | 可并行前提 | 真正集成依赖 |
|---|---|---|---|
| UI-A | F00底座、F14登录 | F14需F00基础组件/认证契约；不可同时改router | V01-T03契约，V01-T04认证实现slice |
| UI-B / R1 | F01资料库、F02保存、F03阅读、F04任务、F15组织基础 | F00通过、R1-CONTRACT、各feature独立；F15等F01可复用列表冻结 | V02/V03真实API；F15最终完善在V10 |
| UI-C / R2 | F05搜索、F11设置基础、F12备份基础、F13回收站 | R2-CONTRACT；search与settings/trash路径独立 | V04发布/搜索/恢复，V06模型预算；F11/F12最终完善在V12 |
| UI-D / R3 | F06Agent、F07审批、F08记忆 | R3-CONTRACT；F06依赖共享运行展示组件及F07审批入口约定 | V08工具与approval BE/RUN；V09权威memory和压缩 |
| UI-E / R4 | F09卡片、F10复习、F11/F12/F15最终完善 | R4-CONTRACT；F10在card组件/schema冻结后可做fixture版 | V10评分/卡片；V12配置、备份/升级恢复 |

每任务区分 `mockReady` 与 `integrationReady`：契约冻结即可实现所有状态的fixture UI；真实行为需要API及相应BE/RUN slice集成。父工作包不能等自己的DONE才开始其前端slice，依赖写到BE/RUN slice，避免循环。QA最终测父包真实场景；只看到Mock页面不将父包标DONE。

共享组件、route注册、Query key增加需要C指定单owner。页面Agent向C提交精确route/key声明和patch草案；C集成后提供新基线。两个页面均需同一组件时先建shared组件slice，两页面消费，不复制两份后再重构。

## 3. 页面任务固定交付

每个Fxx必须交付：路由声明；feature组件；typed query/mutation；状态fixtures；页面状态覆盖表；键盘/焦点检查；响应式截图；真实API端到端报告（若依赖尚未就绪仅可mockReady）；相关readme/已知限制。只交一个TSX静态页面不合格。

标准页面Prompt位于prompts/frontend，每卡都列pageId、route、父包、阶段、feature路径、依赖、特殊状态与验收。worker在开工前把其中contractRev/designRev/assignment填成实际值，并只实现C分配的阶段，例如F12“R2基础”不能提前改R4升级流程。

## 4. 视觉基线与截图协议

初始参考板 `design/reference-board.html` 是设计稿：含4张本地原创线框（资料库、阅读器、Agent/审批、复习）和官方截图链接。它不是React应用，也不证明真实功能已实现。后续生产截图来自运行中的前端，不能拿设计稿截图冒充产品证据。

基线矩阵：全部16页/骨架在1440×900浅色与390×844浅色；重点F01/F03/F06/F07/F10在1440×900暗色；壳/阅读/审批在768×1024；全站200%缩放抽查导航/表单/弹层。截图页稳定fixture至少覆盖默认、empty、error；F04/F06补断流/需处理，F07补conflict/expired，F10补pending/offline。不是所有状态组合做笛卡尔积，语义测试覆盖剩余状态。

截图记录：pageId、stateId、fixtureVersion、contractRev、designRev、viewport、deviceScaleFactor、browser/version、OS/font、theme、时间/随机seed、应用基线hash、截图hash。时间冻结、动画停用、字体加载完成、fixture请求settled后截图；不得用任意sleep假装稳定。动态时间采用固定clock注入，不能mask整个正文掩盖问题。

初次生产截图须C/Q按14的几何和语义检查后写baseline；没有baseline时不声称“视觉回归通过”。后续diff只提示变化，接受新baseline必须附原因和影响，不执行全量自动更新快照掩盖失败。不同OS/font渲染不可直接作为像素级同环境比较；固定CI浏览器环境。

建议初始阈值：稳定区域差异像素≤0.2%且单区域不得有可见错位；文字抗锯齿可在同环境少量容差，关键审批/金额/状态文案由DOM断言，不因截图阈值放过。此值是待V01/首轮截图校准的工程初值，不是现成行业保证。

## 5. 几何与语义硬断言

| 维度 | 必需断言 |
|---|---|
| 壳 | 桌面侧栏216±1px、顶栏56±1px，手机无横向页面溢出，导航顺序统一 |
| 阅读 | 默认正文max720px，正文18px/1.8，右栏关闭后阅读仍居中，引用URL包含固定revision |
| 表单 | label关联输入，必填/错误文本可被读屏感知，提交中不丢草稿，未知结果不双提交 |
| Modal/Drawer | 初始焦点、Tab约束、Esc关闭（安全边界下）、关闭回到触发元素；打开时背景不可交互 |
| 键盘 | 所有主要动作不依赖鼠标；组合输入不触发快捷键；快捷键不覆盖输入编辑 |
| 文本 | 超长中文标题、URL、空来源、长标签、200%字号/缩放不遮操作、不丢状态 |
| 异步 | stale/partial/unknown与成功清楚不同，断流后snapshot和event去重，无无限loading |
| 授权 | 401/403不暴露私密内容；审批参数更改/过期不执行；登出清缓存 |
| 颜色 | 文字对比度、focus可见、图标+文案，不以红绿区分唯一状态 |
| 安全 | 原文脚本不执行，外链rel合规，错误不泄秘密，trace详情不含key/正文 |
| 浏览器 | console无未处理异常，网络无未处理4xx/5xx循环，取消请求不制造假error |

## 6. 十条真实端到端前端场景

1. 首次初始化→登录→保存粘贴→任务进度→阅读→回资料库保留位置。
2. 保存同一请求响应丢失→查询幂等结果→只有一个条目；解析失败保留原输入并可重试。
3. 搜索→固定旧revision阅读→新版本提示→明确切换；不混合引用。
4. SSE断开→状态提示→snapshot恢复→不出现重复消息或假终态。
5. Agent读取多篇→引用可定位→proposal→人工批准→数据库效果一次→UI显示结果。
6. 审批前目标被修改→409冲突→无效果→重新提议；过期/拒绝同样验证。
7. 显式新增记忆→下一会话使用→撤销→下一新授权call不使用；UI边界与实际一致。
8. 长任务触发压缩→重启Runner→UI恢复已提交状态→继续任务；不显示隐藏思维。
9. 四类手动卡→复习→同requestId重复评分→不重复推进；断网不虚假提交；AI关闭仍可用。
10. 完整备份→验证→新实例恢复→阅读/检索/卡片与引用检查；原实例保留。

## 8. 不做什么

不把截图当后端验收，不对所有动画/文字做脆弱逐像素断言，不自动接受新基线，不让前端替Java承担最终权限/预算/评分规则，不以手机适配为由删除复杂状态或审批信息。
