# 10 最终成品与验收契约｜给实现与QA Agent

## 1. 成品定义

目标版本为Larder v1.0：一个可由其他开发者部署、实际保存私人资料、阅读搜索、使用Agent整理并复习的自托管产品；同一项目包含完整Java业务后端与Python Agent运行时。

“成品”同时指用户可用的界面、可恢复的数据、受限且可追溯的Agent、可安装的发布产物和有证据的工程机制。只有后端接口或截图不算完成，只有测试stub也不算完成。

本文件是产品完成判据，不是当前已经实现的能力声明。不得把此清单复制为已完成README。

## 2. 必须可演示的用户流程

| ID | 演示步骤 | 通过标准 | 关联版本 |
|---|---|---|---|
| P01 | 新目录按安装文档启动，设置管理员，重新登录 | 默认仅loopback入口；八服务可诊断，无默认公网密码；刷新会话正确 | V01/V12 |
| P02 | AI关闭，保存公开网页和粘贴正文，标签/笔记/阅读 | 保存成功后持久；抓取失败保留输入；重启后内容仍在 | V02/V03 |
| P03 | 搜索关键词，点高亮跳原文；重抓同时搜索 | 命中绑定revision/chunk；旧发布版有标记；无半成品/已删除结果 | V04 |
| P04 | 处理文本PDF、字幕及合法音频文件 | 页码/时间源自输入；不支持格式明确说明，不伪造正文 | V06 |
| P05 | 摘要/关键句/标签建议，核对引用并接受标签 | 摘要失败不阻断阅读；用户数据变更前可预览；引用可定位 | V06/V08 |
| P06 | keyword/semantic/hybrid对比，模拟embedding故障 | 双路/RRF真实执行；明确降级；有逐query评测 | V07 |
| P07 | Agent跨条目比较，展示工具与证据 | 真正产生并执行受限工具调用，不只是一次长prompt；缺证据可拒答 | V08 |
| P08 | Agent建议加入集合，批准；再改参数/重复执行 | 正确批准应用一次；篡改/过期/旧版本拒绝；有action审计 | V08 |
| P09 | 确认长期记忆，新会话使用，再替代和撤销 | scope召回；新授权调用不含已撤销版本，旧缓存不会复活记忆 | V09 |
| P10 | 长任务触发压缩后中断并恢复 | 原日志保留，恢复有效context，关键事实/引用核对，不假称零重复收费 | V05/V09 |
| P11 | 手动和AI制作四型卡，评分、重复评分、查看旧来源 | 问答/填空/默写/时间戳均可用；评分幂等；AI关闭手动复习仍可用 | V10 |
| P12 | 导出、回收站恢复、完整备份并在新实例恢复 | 原实例不覆盖；正文/版本/笔记/记忆/卡片/任务引用校验通过 | V04/V12 |

P04允许平台字幕抓取不稳定，但用户上传字幕/合法音频的主路径必须真实可用。OCR、更多站点、翻译与周报属于P2，不计入v1.0强制清单。四卡型属于已承诺P1，不能从完成清单删除。

## 4. 页面和交互完成标准

所有01定义的页面必须接真实API，业务关键按钮不能只弹toast。列表/详情/搜索/Agent/复习/设置都有加载、空、错误、降级和登录失效状态；刷新能恢复服务端状态。

处理页区分正文可读、索引状态和AI状态；用户能看到取消/重试是否被接受。审批页显示准确目标、改动和来源，不只显示“是否允许”。记忆管理可看到当前生效和撤销状态；Agent页面可打开引用和可见工具结果。

阅读器禁不可信脚本；默认不跟踪远端图片。小屏可使用、键盘可操作、焦点明确。优先可理解的错误动作，不要求每页动效、仪表盘或美术达到某个商业品牌风格。

## 5. 发布文件清单

最终仓库须有LICENSE、README、CONTRIBUTING、SECURITY、CHANGELOG、.env.example、精确依赖/镜像清单、Compose、迁移、契约、测试与accept/doctor/backup/restore脚本；发布镜像需有版本与digest。必须提供一套可公开示例数据和安装后的快速体验路径。

README必须区分已实现、实验和计划功能；说明AI是否发送数据、模型配置、支持输入、资源实测环境、维护限制、备份位置及恢复步骤。不放用户私密资料、模型Key或外部项目的效果数字。

开源发布操作仍需用户授权。代码和文档达到release candidate不等于允许创建公开仓库、上传镜像或替用户发布。

## 6. 验收层次与判定

TASK_LOCAL_PASS：该工作包在隔离环境完成；VERSION_INTEGRATED：本版本所有包在统一基线上集成通过；ROUND_ACCEPTED：该轮所有版本与跨版本用户流程通过；RELEASE_READY：P01–P12、E01–E10及发布要求满足。

任何缺失必需项为NOT_READY并列明阻塞。可选live供应商暂不可用时可以通过离线阶段，但不能将最终真实模型验收标为通过。KNOWN_LIMITATION只用于范围明确、非必需的限制，不能掩盖已承诺功能缺失。

## 7. 不做什么

不要求未经验证的高并发/HA数字，不将原型页面当成成品，不以“基本可用”绕过数据恢复和授权，不将论文/商业产品的指标当Larder成绩，不自动发布或替换用户实例。
