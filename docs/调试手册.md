## 1. 现在有什么、没有什么

| 已有 | 状态 |
|---|---|
| 八服务编排（mysql/redis/rabbitmq/meili/minio/api/runner/web） | ✅ 可用 |
| 登录/登出 + CSRF（单管理员） | ✅ 可用 |
| `POST /api/items` 收录（幂等 + URL 去重） | ✅ 可用 |

| artifact 存储（MinIO 不可变对象） | ✅ 可用 |
| Runner 回传发布（`/internal/runs/{runId}/result`） | ✅ 可用（需内部令牌） |
| 前端产品页面（列表/详情/阅读器） | ❌ 只有骨架页（显示 `/api/ping`） |

**结论**：现在调试的是“接口 + 数据 + 日志”，不是“点页面”。

## 5. 数据库调试

### 5.1 连接

```powershell
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysql -ularder -N -B larder -e "SHOW TABLES"'
```

IDEA Database：`127.0.0.1:3306` / 库 `larder` / 用户 `larder` / 密码见 `.env`，
URL 加 `?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC`。

当前表：`app_meta, owner, item, content_revision, job, outbox, idempotency_request, artifact, revision_artifact, inbox, flyway_schema_history`。

### 5.2 常用 SQL

```sql
-- 链路总览
select id, kind, title, current_revision_id, processing_epoch from item order by created_at desc limit 10;
select id, item_id, kind, state, attempt, run_id, lease_owner, lease_token, lease_until from job order by created_at desc limit 10;
select revision_no, id, source_hash, created_at from content_revision order by created_at desc limit 10;

-- 投递/消费
select state, count(*) from outbox group by state;
select event_id, event_type, state, attempt, available_at, relay_owner, relay_token from outbox order by created_at desc limit 10;
select consumer, event_id, job_id, received_at, accepted_at from inbox order by received_at desc limit 10;

-- 幂等
select left(request_key,24) k, state, response_status, created_at from idempotency_request order by created_at desc limit 10;

-- 产物
select id, sha256, bytes, mime, state, object_key from artifact order by created_at desc limit 10;
select * from revision_artifact order by revision_id limit 10;

-- 迁移
select installed_rank, version, description, success from flyway_schema_history order by installed_rank;
```

### 5.3 手工造状态（仅开发环境）

```sql
-- 让 job 租约立即过期，触发对账（V03-T03）
update job set lease_until = utc_timestamp(6) - interval 1 second where id = 'job_xxx';

-- 让 outbox 重新投递（模拟 confirm 丢失）
update outbox set state='PENDING', available_at=utc_timestamp(6) where event_id='out_xxx';

-- 给 job 指定 runId（模拟已派发给 Runner）
update job set run_id='run_debug_1' where id='job_xxx';
```

> 这些操作会改变状态机，**只在本地测试库做**。

## 8. HTTP 接口调试

### 8.1 IDEA HTTP Client（推荐）

打开 `docs/api.http`：

1. 把 `adminPassword` / `internalToken` 换成本机值；
2. 依次执行：① 401 拿 CSRF → ② 登录 → ③ 当前用户 → ④ 收录 → ⑤ SSE → ⑥ 内部回传。

IDEA 会自动保存 cookie；第 ① 步的响应脚本会把 `XSRF-TOKEN` 写进变量。

### 8.2 curl（不依赖 IDE）

```powershell
$jar = "$env:TEMP\larder-cookies.txt"
curl.exe -sS -c $jar -o NUL http://127.0.0.1:8080/api/session
$xsrf = (Get-Content $jar | Where-Object { $_ -match 'XSRF-TOKEN' } | ForEach-Object { ($_ -split "`t")[-1] })
$pw = ((Get-Content .env | Where-Object { $_ -match '^LARDER_ADMIN_PASSWORD=' }) -replace '^[^=]+=','').Trim()
$body = '{"username":"admin","password":"' + $pw + '"}'
[IO.File]::WriteAllText("$env:TEMP\login.json", $body, (New-Object Text.UTF8Encoding($false)))
curl.exe -sS -b $jar -c $jar -H "X-XSRF-TOKEN: $xsrf" -H 'Content-Type: application/json' --data-binary "@$env:TEMP\login.json" http://127.0.0.1:8080/api/session
```

收录与 SSE：

```powershell
curl.exe -sS -b $jar -H "X-XSRF-TOKEN: $xsrf" -H "Idempotency-Key: debug-0001" -H "Content-Type: application/json" `
  -d '{\"kind\":\"WEB\",\"url\":\"https://example.com/debug\"}' http://127.0.0.1:8080/api/items

curl.exe -N -b $jar -H "Last-Event-ID: 0" http://127.0.0.1:8080/api/jobs/<jobId>/events
```

内部回传（不走 session，走令牌；直连 api 8081 或经 nginx 都行）：

```powershell
curl.exe -sS -H "X-Internal-Token: <token>" -H "Content-Type: application/json" `
  --data-binary "@result.json" http://127.0.0.1:8081/internal/runs/<runId>/result
```

### 8.3 状态码速查

| 码 | 含义 | 常见原因 |
|---|---|---|
| 401 | 未登录 / 令牌无效 | 没登录；`X-Internal-Token` 错或为空 |
| 403 | CSRF 校验失败 | POST 没带 `X-XSRF-TOKEN` 或 cookie 不匹配 |
| 400 | 参数不合法 | 缺 `Idempotency-Key`、kind 不支持、URL 非法 |
| 409 | 冲突 | 同 key 不同 body（`IDEMPOTENCY_CONFLICT`）、旧 epoch（`EPOCH_SUPERSEDED`）、run 不匹配 |
| 503 | 内部令牌未配置 | `LARDER_INTERNAL_TOKEN` 为空（fail closed） |
| 502 | nginx 连不上 api | api 重建后 IP 变了，`docker compose restart web` |
| 504 | 请求超时 | 数据库锁等待（如外键锁）或下游慢 |

## 9. IDEA 断点调试后端

1. 起依赖并释放 8080：

```powershell
docker compose up -d --wait mysql rabbitmq minio
docker compose stop api web
```

2. `scripts/dev/print-debug-env.ps1` 生成环境变量，粘进
   `Run → Edit Configurations → Environment variables`；
3. Debug 运行 `com.larder.LarderApplication`；
4. 断点建议：

| 想看什么 | 断点 |
|---|---|
| 幂等/去重 | `ItemIngestService.ingest` |
| 发布事务/旧 epoch | `RevisionPublisher.publish` |
| 内部令牌 | `RunnerResultController.publish` |
| SSE 快照 | `JobEventsController.events` |
| 投递/退避 | `OutboxStore.claim`、`OutboxRelay.runOnce` |
| 对账 | `JobReconciler.runOnce` |

> 直接本地跑更快。


```powershell

```

单独试抓取/抽取/分段：

```python
from larder_runner.stages.fetch import fetch, UrlGuard
r = fetch("https://example.com", guard=UrlGuard())
print(r.status, r.content_type, len(r.body))

from larder_runner.stages.extract import extract
print(extract(r.body, r.content_type).text[:200])
```

## 12. 故障排查表

| 症状 | 原因 | 处理 |
|---|---|---|
| `docker info` 报 `cannot find the file specified` | Docker Desktop 未运行 | 启动 Docker Desktop，等 daemon ready |
| `401` 登录失败 | 密码不对 / 容器环境变量旧 | 对比容器与 `.env`；`docker compose up -d` 重建 api |
| `403` POST 失败 | 缺 CSRF | 先 GET 拿 `XSRF-TOKEN`，请求头带上 |
| `409 IDEMPOTENCY_CONFLICT` | 同 key 不同 body | 换 key，或让 body 一致 |
| `409 EPOCH_SUPERSEDED` | job 的 processing_epoch 已变 | 用当前 epoch 重新回传 |
| `503 INTERNAL_AUTH_DISABLED` | 内部令牌为空 | 在 `.env` 设 `LARDER_INTERNAL_TOKEN` 并重建 api |
| `502` 经 8080 | nginx 上游 IP 过期 | `docker compose restart web` |
| `504` | 数据库锁等待（常见外键未提交） | 查 `information_schema.innodb_trx`；确认事务边界 |
| MySQL 忽略 my.cnf 告警 | Windows bind mount 权限 0777 | 已改用 compose `command` 传参，忽略该告警 |
| Flyway 没跑 | 只加了 flyway-core | 必须用 `spring-boot-starter-flyway` |
| `@WebMvcTest` 找不到 | Boot 4 包名变了 | `org.springframework.boot.webmvc.test.autoconfigure` + `spring-boot-starter-webmvc-test` |
| PS 脚本语法乱码 | 无 BOM 的 UTF-8 | 保存为 UTF-8 with BOM |
| `git push` 代理错误 | 全局 git 代理指向已停端口 | `git -c http.proxy= -c https.proxy= push` |
| pytest 无法 spawn | Smart App Control 拦截 uv venv | 用系统 Python + `PYTHONPATH=runner/src`，或让 accept 回退 |
| `NoSuchBean sqlSessionFactory` | 启动类 `@MapperScan` 污染切片测试 | 去掉注解，Mapper 用 `@Mapper` |

## 13. 巡检 SQL（本地）

```sql
-- 卡在 RUNNING 且租约过期的 job（对账应该会处理）
select id, attempt, lease_until from job
 where state='RUNNING' and (lease_until is null or lease_until < utc_timestamp(6));

-- 积压的 outbox
select state, count(*), min(available_at) from outbox group by state;

-- DEAD 事件（需要人工看）
select event_id, event_type, attempt from outbox where state='DEAD';

-- 最近发布
select i.id, i.current_revision_id, r.revision_no, r.created_at
  from item i left join content_revision r on r.id=i.current_revision_id
 order by i.created_at desc limit 10;
```

## 14. 安全与边界

1. `.env` 不入库；不要截图/粘贴真实密码到聊天或 issue；
2. 端到端脚本会**删除开发队列、重启容器**，不要在生产库/生产队列跑；
3. 内部令牌是共享密钥，只在容器网络或本机回环使用；
4. `reports/` 里的日志可能含 traceId/请求体，外发前先脱敏；
5. 不要用 `docker compose down -v`（会删数据卷）。
