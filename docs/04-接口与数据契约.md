# 04 接口与数据契约

## 1. 契约约定

协议v1。Java公开普通JSON成功体采用18的ApiResponse<T>，错误体保留本文ApiErrorResponse；Runner/SSE/文件不自动套壳。配套公共响应schema见contracts/public-api-common.schema.json。ID统一为带字母前缀的不透明ASCII字符串，2–64字符，客户端不得解析前缀获取授权。UTF-8 JSON，时间UTC ISO8601；数据库UTC微秒。ID为服务端生成的不透明字符串，客户端不得从ID推断授权。HTTP语义保留；错误统一`{code,message,traceId,retryable,details}`。401未登录、403无权、404不存在、409状态/幂等冲突、413过大、429限额、503依赖不可用。

命令型POST使用Idempotency-Key或明确requestId；同owner+route+key+相同请求hash返回原结果，同key不同请求409。入参schema严格拒绝未知字段，`expectedVersion`参与写入竞争检查。服务器不能把前端提交的ownerId当授权来源。

机器契约在 [Runner OpenAPI](../contracts/runner.openapi.json) 及同目录schema。它覆盖最先需要冻结的Runner接口、事件和日志；Java公开API/内部工具的完整OpenAPI及SQL迁移分别由V01、V08生成，以下表格是实现要求，不能假装已存在所有接口代码。

## 2. 标识与状态映射

| 标识 | 作用 / 不得混用 |
|---|---|
| itemId / revisionId / chunkId | 用户入口 / 不可变正文 / 版本内段落 |
| generationId | 该条目的一个索引构建版本，固定revision和索引profile |
| jobId / attempt / runId | Java业务任务 / 实际执行尝试 / Runner运行；lease接管不增加attempt或run |
| eventId / seq | 唯一事件 / 单run递增序号；不同run不能共用seq去重 |
| leaseToken / processingEpoch | worker持有代次 / 用户处理请求代次；两者都必须检查 |
| callId / actionId / approvalId | 一次调用 / 幂等业务效果 / 绑定内容的授权 |
| memoryId / memoryVersion / policyEpoch | 记忆条目 / 内容版本 / 权限/记忆变化后的授权代次 |

| 对象 | 状态 |
|---|---|
| job | QUEUED、RUNNING、RETRY_WAIT、NEEDS_DECISION、SUCCEEDED、FAILED、CANCELLED、SUPERSEDED |
| run | QUEUED、RUNNING、WAITING_APPROVAL、NEEDS_DECISION、SUCCEEDED、FAILED、CANCELLED、CORRUPT |
| generation | BUILDING、VALIDATING、READY、ACTIVE、FAILED、SUPERSEDED；ACTIVE由item发布指针定义 |
| call | PLANNED、IN_FLIGHT、SUCCEEDED、FAILED_DEFINITE、UNKNOWN |
| approval | PENDING、APPROVED、APPLIED、REJECTED、EXPIRED、STALE |
| memory | ACTIVE、SUPERSEDED、TOMBSTONED |

状态事件和对应数据库修改同事务；Runner以持久日志提交为状态事实。Java可以在单事务内结束job并登记新阶段job，不把两个对象的状态名直接照搬。

## 3. MySQL逻辑模型与唯一约束

本表是逻辑摘要；字段/索引/约束细化到16和contracts/mysql-schema.sql（43表，带COMMENT）。DDL为尚未在真实MySQL8.4执行的设计基线，须隔离验证并按版本拆迁移。业务字段不可只以无约束JSON糊成一列。

| 表组 | 必要字段与约束 |
|---|---|
| owner / session | owner时区、password_hash、settings_version；session在DB持久，单管理员 |
| item | owner_id、kind、original_url、normalized_url、url_hash、current_revision_id、active_generation_id、processing_epoch、metadata_version、row_version、deleted_at；UNIQUE(owner_id,url_hash)，无URL时NULL |
| content_revision / chunk | item_id、revision_no、source_hash、extractor/chunker_version、manifest；UNIQUE(item_id,revision_no)；chunk含ordinal、text/hash、page/time，UNIQUE(revision_id,ordinal) |
| artifact | owner_id、bucket、key、object_version、sha256、bytes、mime、state；key不可由用户任意指定；绑定对象引用表记录revision/run关系 |
| job | item_id、kind、input_revision、processing_epoch、attempt、run_id、state、lease_owner/token/until、next_attempt_at、next_reconcile_at、payload_hash、error；索引(state,next_attempt_at/id)、(state,lease_until)、(state,next_reconcile_at) |
| outbox / inbox | event_id唯一，aggregate、type、payload_hash、available_at、relay_lease、state、attempt；inbox唯一(consumer,event_id)，与持久接管同事务 |
| job_event / run_receipt | job事件(seq)；run_receipt唯一(run_id,seq)，含payload_hash和applied_at；消费游标与业务效果同事务 |
| index_generation | item/revision、profile/schema、manifest_hash、state、expected_epoch、task_uids、validation_report_ref；generation内chunk ID唯一 |
| metadata_projection | item、index_profile、desired/applied_metadata_version、task_uids；轮转校验外部实际版本防迟到覆盖 |
| tag / item_tag / collection / collection_item | owner、规范化名称、关联唯一；首版手动集合，规则集合单独版本化规则 |
| note / reading_position | item、可选revision/chunk、Markdown、row_version；引用旧版不得静默搬移 |
| card / review_state / review_log | card type、source anchor、front/back/rubric、state；review_state row_version；review_log唯一(card_id,request_id)，保存before/after、grade、scheduler_version |
| proposal / approval / action_result | run、owner、action_type、target_versions、payload_hash、expiry、status；actionId唯一；业务效果+APPLIED+result+audit同事务 |
| memory_slot / memory / memory_version | slot唯一(owner,scope,key)，锁slot保证唯一活动版本；version保存source、value、status、hash、supersedes、revoked_at |
| run_scope / model_call_grant | run授权资源、expiry、policy_epoch；grant绑定callId、budget、memory refs、evidence refs、requestHash、授权时间，禁止跨call复用 |
| budget_day / reservation / usage_ledger | owner+day唯一，run/call预留唯一；usage唯一(call_id,usage_version)，unknown独立状态 |
| idempotency_request / audit_event | 请求key/route/body_hash/response唯一；审计actor/action/target/trace/time，敏感正文不入日志 |

长URL存原值，唯一索引用hash，碰撞时比较规范化原值。引用外键必须保证chunk属于revision、revision属于item。校验目标版本不能只检查ID存在。软删除不依赖重置唯一键实现，恢复同一item。

## 5. Runner HTTP与SSE

| 接口 | 行为 |
|---|---|
| POST `/v1/runs` | 严格run-request schema；首次202；同runId同payload返回现有状态200；不同payload409 |
| GET `/v1/runs/{runId}` | 持久快照、lastSeq、stage、usage、manifest、error |
| GET `/v1/runs/{runId}/events` | SSE；Last-Event-ID为seq，重复发送允许，重复应用禁止 |
| POST `/v1/runs/{runId}/cancel` | 持久记录取消请求；阻止新阶段，不能保证供应商停止计费 |
| POST `/v1/runs/{runId}/resume` | decisionId、CONTINUE/RETRY_UNKNOWN；向Java验证决定，不以请求字段直接获得权限 |
| GET `/v1/runs/{runId}/artifacts/{artifactId}` | 有界流式产物读取；只能该run下映射文件 |
| POST `/v1/runs/{runId}/ack` | Java已收取/发布manifest的确认；不意味着可自动物理删除 |
| POST `/v1/embeddings` | mode=EMBED的相同run请求；200返回已完成状态和向量产物manifest，202仍在处理；向量经artifact接口读取，已有run可GET对账 |

请求头内部服务身份+Idempotency-Key=runId。scope包含owner与明确授权集合，但Java内部接口仍按持久run_scope校验；不能信Runner传来任意owner。budgetGrantId引用持久授权，秘密token不写入journal，重启后按身份重新取得。

SSE映射日志中可公开的事件；所有状态事件必须先fsync。数据含protocolVersion、runId、seq、eventId、type、time、payload。每10秒comment心跳，不占seq；SSE空闲连接超时和run deadline分开。未知event type在同主版本按契约兼容规则记录并对账，不能猜状态。

Java按(runId,seq)去重，同seq不同hash是协议损坏；缺口补拉，cursor已不可用410并读快照。事件、receipt、业务副作用在同一MySQL事务。终态可GET恢复，SSE不是唯一成功事实源。大正文、embedding和压缩结果只通过artifact传输。

Manifest含schemaVersion、runId、artifacts[id/hash/bytes/mime]、chunkCount、sourceVersions与warnings。Java重新计算hash、检查计数和引用，再写MinIO及DB。不得信任未经验证的路径、object key、页码和时间戳。

## 6. Java内部工具与授权

所有内部路由不经Web代理公开，使用服务身份和绑定run的短期capability。原始token只在内存/安全配置中，刷新不会改变run scope。

| 路由（统一 `/internal/runs/{runId}` 前缀） | 权威检查 |
|---|---|
| GET `/inputs/{inputId}` | owner、run、输入授予范围；固定内部地址，不接受用户指定内部URL |
| POST `/tools/search` | 复用搜索发布/权限复核，登记可读取候选 |
| POST `/tools/read-chunks`、`/tools/neighbors` | 限制列表长度、归属、已授权资源、删除状态 |
| POST `/tools/recall-memory` | scope候选→MySQL ACTIVE/version复核 |
| POST `/proposals` | 只允许已注册动作、参数schema、目标版本；返回proposal/approval |
| GET `/approvals/{approvalId}` | 限当前run/owner，返回当前状态和绑定hash |
| POST `/actions/{actionId}/apply` | action结果幂等；审批hash/资源版本/expiry/run复核后单事务应用 |
| GET `/actions/{actionId}` | 外部响应未知时查询已经发生的业务效果 |
| POST `/authorize-model-call` | requestHash、memory/evidence refs、budget与policyEpoch；事务授权线性化点 |
| POST `/usage` | callId/usageVersion幂等结算，不反复累计重复SSE |
| GET `/decisions/{decisionId}` | 校验run恢复/UNKNOWN重试决定，不能自行创建批准 |

工具授权可允许访问某个已固定历史revision；用户删除则仍禁止。已授权在途模型请求不可收回，新的call授权必须使用最新权限/记忆状态。该边界必须在UI和评测中一致。

## 7. 错误与降级统一表

| code | retryable / 行为 |
|---|---|
| FETCH_TIMEOUT / RATE_LIMITED | 有限退避，尊重Retry-After与总deadline |
| NEED_LOGIN / EXTRACT_EMPTY / OCR_UNSUPPORTED | 不自动反复重试；保留原输入，提供手动路径 |
| RUN_PAYLOAD_CONFLICT / STALE_WRITE / APPROVAL_STALE | 409；用户刷新或重新审批，不静默套用 |
| LEASE_LOST / PROCESSING_SUPERSEDED | 内部拒绝旧提交；不得继续发布 |
| INDEX_TASK_FAILED / INDEX_VALIDATION_FAILED | 旧active generation仍服务，记录失败 |
| UNKNOWN_PROVIDER_RESULT | NEEDS_DECISION，默认不重复计费请求 |
| INVALID_CITATION / INVALID_MODEL_OUTPUT | 最多一次预算内修复，仍错终止 |
| BUDGET_EXCEEDED / TOOL_LIMIT_EXCEEDED | 停止后续调用，返回有限结果或失败 |
| FORBIDDEN_TARGET / SSRF_BLOCKED | 拒绝，不将其改成“网络超时”隐藏原因 |
| JOURNAL_CORRUPT / CORRUPT_ARTIFACT | 保留现场，停run，诊断；不可自动清空历史 |

## 8. 契约演进与不做什么

新增可选响应字段可向后兼容；删除字段、改状态含义或授权语义提升protocolVersion。服务启动检查支持范围，拒绝不兼容版本。Mock与真实Runner共用schema和样例，不能维护假接口特例。

本次交付明确标注未实库验证的DDL设计，不交付假装已实现的业务工程。机器契约是可验证的起点，后续任务必须补全公开API、内部工具schema、迁移和生成类型；不允许凭“文档里大概是这样”自行发明不兼容字段。
