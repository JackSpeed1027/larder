## 4. 命令与报告契约

**当前可运行的是设计包工具，不是业务测试：**

```powershell
python scripts/validate_handoff.py
python scripts/validate_execution.py
python scripts/plan_dispatch.py --batch V01-T01
python scripts/build_task_prompts.py --check
```

**以下由V01及对应任务实现，当前不是已经通过的业务命令：**

```powershell
docker compose config --quiet
docker compose up -d --wait
.\backend\mvnw.cmd -f .\backend\pom.xml verify -DfailIfNoTests=true
uv run --project runner pytest runner/tests -m "not live" -q
pnpm --dir frontend test --run
pnpm --dir frontend build
python scripts/accept.py --task V03-T04 --profile offline
python scripts/accept.py --stage V11 --profile live
```

Linux/WSL用`./backend/mvnw`；Maven verify配置Failsafe且缺少预期集成测试失败。accept检查任务必需测试确实存在且执行，不能因为skip、缺Docker或模型不可用就返回PASS。live需要显式配置供应商和预算；默认CI不调用收费API。

报告目录`reports/<taskId>/<runId>/`，summary.json包含status、commands/exitCode、环境、versions、pass/fail/skip、样本数、artifacts与limitations。性能、效果和故障测试分别报告，任何测试失败要定位范围内原因，不能删断言蒙混通过。

## 5. 故障/正确性验收矩阵

| ID / 阶段 | 输入或注入 | 必须观察到 |
|---|---|---|
| A01/V02 | 同key并发100次、同key不同body | 同一item/job；冲突409，不靠前端禁用按钮 |
| A02/V03 | DB已提交但MQ不可达 | Outbox保留，服务恢复可补发；失败不伪装成功处理 |

| A06/V03 | 两次重抓，旧job后完成 | 即使lease有效，processingEpoch拒绝旧结果 |

| A17/V07 | keyword/semantic/RRF对照 | 固定qrels逐query报告、miss归因、端到端时延 |

| A20/V08 | Java应用成功但Runner响应丢失 | actionId查询原结果，数据库效果只有一次 |
| A21/V09 | 记忆替代/墓碑+旧索引旧缓存 | 新授权调用只注入最新有效版本 |
| A22/V09 | 撤销与call授权竞争、重启旧context | 以授权事务为界，已在途单列，不能复活失效记忆 |

| A25/V10 | 重复评分与不同请求竞争 | 相同requestId返原结果；旧stateVersion409 |

## 6. 评测数据与指标

检索先人工构建约50条query及对应qrels，逐步扩量；AI八类任务每类先5个人工rubric样本。数量是首批工作量建议，不是实测样本。开发集与冻结验收集分开，不反复对验收集调prompt而不说明。

Document Recall@5按query计算前5文档命中相关文档比例后平均；Hit@5按至少命中一个的query比例；MRR记录首个相关排名。逐chunk生成候选，但文档级评测先按item聚合，不能混用分母。记录keyword miss、dense miss、ranking miss、publication/permission filter miss。

AI质量记录引用定位率、人工支持率、卡片可答率、任务通过率和拒答准确性；全体失败/超时计入分母。原文引用不存在与引用存在但不支持结论分开。效果数字写`__%`，时延`__ms`，样本`__/__`，直到真实报告产生。

每个指标需数据版本、代码版本、模型/prompt、硬件、并发、冷/热缓存、重试策略、原始样本和聚合脚本。并发收益对照相同调用集合；质量消融可能结论是没有改善，也要保留。

## 7. 阶段放行与范围处理

V04前不扩大到多平台下载/复杂OCR；V08前不能以普通聊天冒充工具Agent；V09前不能将三个设置字段冒充长期记忆；V11前不能预填优秀效果数字。每版放行看行为和证据，不看文件数或组件是否在docker ps中出现。

若进度落后，先延后P2、视觉装饰、额外站点适配、更多转写供应商和规则集合。核心机制仍保留；确需延期或删核心时，报告缺口、剩余估时和用户可选方案，不自行决定。可先拿V08已有证据准备简历，未完成记忆/压缩不得提前写已实现。

## 8. 不做什么

不拿设计包验证当业务验收，不以stub通过当真实模型质量，不对用户库进行故障注入，不自动push或发布，不为赶日期删除可靠性、权限、记忆和压缩任务。
