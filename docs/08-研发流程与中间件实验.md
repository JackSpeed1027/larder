# 08 公司式研发流程与中间件实验

本项目以面试与系统学习为首要目标，同时完成可开源使用的产品。以下要求补充V01–V12，不因用户量小而取消数据库、MQ、缓存、对象存储或工程实验。不同公司流程不同，本章提供可以实际执行的一套研发基线，不声称复制所有公司的全部设施。

## 1. 调研结论与学习路线

| 主题 | 官方资料核对结论 | Larder实验和产物 |
|---|---|---|
| MySQL事务 | InnoDB支持多个隔离级别，隔离选择影响读取与锁行为；不能把所有竞争归结为加事务即可 | L01：RR/RC下并发收录、锁定读取、死锁重试；保存会话时间线、SQL和最终状态。依据[隔离级别文档](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html) |
| MySQL索引 | 任务扫描与列表读取需要不同访问路径，不能凭字段名判断索引有效 | L02：对job/outbox/item列表执行EXPLAIN ANALYZE，比较联合索引、深分页与游标；记录扫描行数、执行计划和锁等待 |
| Redis缓存 | 缓存是派生副本，失效通知与TTL不等于数据库事务 | L03：向量缓存的穿透、热点并发回源、TTL抖动、失效与连接池故障；记录命中率、回源数、时延，不缓存最终权限结论 |
| RabbitMQ复制 | quorum queue使用Raft复制；可用性依赖多数派，不是创建队列即可获得集群HA | L04：隔离环境三节点quorum队列，杀leader与丢多数派，比较confirm、重投和恢复。依据[quorum文档](https://www.rabbitmq.com/docs/quorum-queues) |
| 对象存储 | 本地发布指针不能让对象写入与数据库共同事务化 | L05：分片失败、对象已写DB未提交、预签名过期、缺对象；校验SHA与引用，保留孤立对象报告 |
| 可观测 | trace由跨组件span组成，需要上下文传播才能关联调用 | L06：HTTP→Outbox/MQ→Java worker→Runner→工具call建立trace/link；失败能从用户trace定位。依据[OpenTelemetry traces](https://opentelemetry.io/docs/concepts/signals/traces/) |
| 迁移 | Flyway validate检查迁移与历史的名称、类型、checksum等差异 | L07：在测试库改已应用迁移应失败；验证扩展字段、旧应用兼容、失败恢复。依据[Flyway validate](https://documentation.red-gate.com/fd/validate-277578898.html) |
| 集成验证 | Testcontainers可用容器化真实依赖执行测试 | L08：对照mock与真实MySQL/MQ/Meili/S3故障语义，避免只测Java内存对象。依据[Testcontainers](https://java.testcontainers.org/) |

实验均操作隔离测试库、专用卷、生成语料和临时身份。不得把kill、损坏文件、修改迁移、网络隔离用在用户正式实例。MQ三节点和观测组件是实验/运维叠加配置，不产生另一套业务实现。

## 2. 公司研发通常需要的交付物

| 阶段 | 交付物 | 进入下一阶段的条件 |
|---|---|---|
| 需求 | 01中的功能ID、用户故事、输入输出、非目标、异常交互 | 每个功能有可观察验收，不只写“支持XX” |
| 技术设计 | 02/03/04、ADR、时序、状态、SQL与接口 | 权威源、幂等、失败窗口、授权和预算说清楚 |
| 任务拆分 | tasks清单、依赖、范围、测试、风险 | 单次改动可review；契约变更覆盖所有消费者 |
| 开发 | 分支、迁移、代码、单测、契约测试 | 静态检查及快速测试通过，秘密不入库 |
| 联调 | Mock与真实Runner一致、Testcontainers、浏览器E2E | 正常/失败/重试/取消完整，不能只有happy path |
| 发布准备 | 镜像digest、变更日志、已知问题、回滚/恢复方案 | 安装、升级、数据兼容和恢复演练通过 |
| 运行 | 仪表盘、告警、runbook、故障复盘 | 告警有责任动作，恢复记录可复查 |
| 开源 | LICENSE、CONTRIBUTING、SECURITY、issue/PR模板、示例数据、截图 | 新机器按README成功使用，示例不含私密内容 |

这些是待实现阶段的产物清单，本包不假称已经配置CI、发布镜像或跑过演练。项目源码计划MIT，依赖和模型/数据许可逐项记录，不能把所有依赖一律重新标MIT。

## 3. 完整仓库目标结构

```text
larder/
  README.md  AGENTS.md  LICENSE  CONTRIBUTING.md  SECURITY.md  CHANGELOG.md
  backend/               # 02定义的业务包、Flyway迁移、单元/集成测试
  runner/                # 03定义的runtime、tools、memory、compression、evals
  frontend/              # pages/components/api/hooks/stores/styles
  contracts/             # public/internal/runner OpenAPI、schema、golden fixtures
  deploy/                # 发布compose、开发override、观测与隔离实验叠加配置
  scripts/               # accept、doctor、backup、restore、实验与校验
  tasks/                 # 任务状态和依赖
  docs/                  # 当前设计；adr/ runbooks/ release/复盘按任务新增
  evals/                 # dataset说明、query/qrels、rubrics、模型配置
  reports/               # 脱敏原始结果；大产物不直接塞进Git
  .github/workflows/     # PR检查、集成、构建、安全、release
  .github/ISSUE_TEMPLATE/  # bug/功能/设计变更
```

生成文件、秘密、用户数据、模型响应全文与大文件纳入.gitignore或受控产物存储。设计文档随实际机制修订，不能设置成永远禁止修改导致规格与实现分离。

## 4. CI与质量门禁

PR快速检查：格式/lint、Java编译及单测、Python单测、TS类型/单测/构建、OpenAPI兼容与schema样例、Flyway validate、秘密扫描。无测试和意外skip应失败或明确例外，不能返回全绿。

集成任务：真实MySQL/Rabbit/Redis/Meili/MinIO容器，运行状态、并发、幂等与故障用例；浏览器验证收录→阅读→搜索→审批→复习。网络和CPU密集实验独立job，设超时、资源限制、报告保留。

供应链：固定锁文件和镜像digest，生成SBOM，依赖/容器漏洞扫描及license清单。发现风险先评估是否影响当前路径；高风险例外必须记录原因和处理期限，不能只为绿灯跳过检查。外部PR不获得发布密钥或模型Key。

发布流程：用户批准后构建带版本的镜像→隔离环境smoke→备份和迁移验证→发布说明→用户批准上线。当前任务没有授权这些外部发布动作。默认发布不是自动部署到用户机器。

## 5. 可观测与服务目标

采用Micrometer/Prometheus指标、OpenTelemetry跨端trace，Grafana展示队列年龄、失败、索引延迟、模型成本和资源。观测服务作为部署叠加项，不改变核心业务语义；本地最小运行仍须有结构化日志和指标端点。

异步跨分钟任务使用span link或有界阶段span，避免一个无限跨度span吞没全部细节。记录用户请求、Outbox发布、MQ接管、Runner阶段、工具call、模型调用和审批action；不将token/正文当高基数metrics label。trace中不放Key或用户原文。

先定义SLI和测量窗口，再确定SLO：API成功率、非AI请求P95、job排队年龄、索引可见延迟、UNKNOWN比例、恢复RTO、预算偏差。初始阈值是设计警戒值，不能写成已达成的99.9%。压测同时报告吞吐、错误、排队、资源和长尾，不能只给一个QPS。

每条告警关联runbook：症状→只读检查→可能原因→保留数据的缓解→验证→升级处理。至少覆盖MQ积压、租约频繁回收、索引不收敛、模型费用未知、磁盘不足、journal损坏和备份失效。

## 6. ADR、评审与复盘模板

ADR必须包含：问题、选项、决定、为什么、代价、数据/接口影响、迁移与回退、验证、何时重新考虑。需要ADR的事项包括搜索profile迁移、MinIO实现替换、JSONL协议变更、审批授权语义变更和新增外部工具。

PR说明：触发场景→改后行为→状态/数据变化→验证→风险，不只列改了哪些文件。评审重点是事务边界、失效窗口、权限、资源上限、数据兼容和恢复，不只看代码风格。

故障复盘：时间线、用户影响、根因、为什么测试没发现、恢复动作、数据是否受影响、回归用例和改进任务。故障实验有价值，应把“发现并修复了什么”写入学习笔记，不能只追求一次全部通过。

## 7. 周期增量与不做什么

V01建立CI基础；V03/V04安排L01/L02/L05；V07做L03；V11做L04/L06/L08；V12做L07和开源发布材料。基础研发流程计入328小时，完整三节点故障、观测大盘和深入SQL调优另预留40–80小时，完整深度目标可能需要约20–22周。若仍需3月先投递，用已完成证据写简历，其余继续开发，不把未来成果提前写成事实。

不为了“公司都这样”强行引入无任务的Kubernetes、分库分表、服务网格或多地域容灾。需要学习时另设隔离实验与可验证问题；这不影响当前已明确保留的中间件与全部Agent机制。
