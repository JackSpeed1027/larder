## 1. 与参考简历相当的深度如何落地

参考的是“问题→机制→验证→结果”的深度，以及一个项目分后端和智能体两块的组织形式。公司、时间、用例数量、召回率、耗时降幅等均不能复制成Larder成果。

## 2. 保留与修正决策

| 决策 | 为什么 / 代价 |
|---|---|
| 保留全部主要中间件 | 用户明确希望达到双模块工程深度；每个组件有实际职责和故障用例，代价是资源与运维复杂度增加 |
| MySQL为提交权威，Redis为派生/限流 | Redis仍有实际用途；防止缓存故障或锁过期破坏最终一致性，代价是DB需维护lease和预算 |
| MQ通知与长任务分离 | 避免分钟级未ack消息占满消费者；DB持久接管后ack，必须实现补偿扫描 |
| IndexGeneration按item而非每次全库 | 保留隔离构建与发布深度，控制重建成本；全库schema/模型切换仍需维护窗口 |
| 关键词+向量+RRF，不错误称Meili BM25 | 保留检索融合与评测，按实际能力命名；需要独立query向量与profile管理 |
| JSONL权威，不替换SQLite | 保留参考目标中的运行时工程问题；必须承担尾写、日志校验、快照和恢复测试成本 |
| 跨Session记忆真实实现 | 用户长期学习目标与专题约定需要作用域和生命周期；语言长度这类普通设置不冒充语义记忆 |
| 审批绑定hash/版本/run | 人工确认有明确业务意义；多一套proposal/action审计，但能防止批准后偷换参数 |
| 模型UNKNOWN保留 | 可靠性需要承认外部不可知窗口；自动重试更克制，用户可能需要一次决定 |
| 功能/AI/索引状态分离 | 关闭AI或更新失败不破坏阅读；UI状态略复杂但更准确 |
| 不自动合并近似内容或删历史 | 避免丢来源/笔记/引用；需要占用报告和显式清理流程 |
| 单一部署，固定原版本线 | 不维护多套实现；遇到维护/兼容风险先验证和ADR，不随意整栈升级 |

以下旧说法不沿用：Meili默认等于BM25；Checkpoint保证任何崩溃下不重复计费；单节点MQ等于HA；JSONL文件与Checkpoint天然同事务；无字幕评论可以替代视频正文；FSRS没有历史就不能运行；模拟复习证明真实回忆率。

## 4. 一个项目、两个模块的简历成稿模板

以下仅在实现并补全证据后使用。日期按实际投入填写；未完成条目整条删除或明确“进行中”，不能只删掉占位数字留下已完成语气。

**Larder · 个人内容库与智能学习工作台**　`实际日期—实际日期`

项目描述：面向个人资料管理与复习的自托管应用，统一保存网页、PDF和字幕/转录内容；后端负责不可变内容版本、可靠异步处理、可信检索和学习调度，独立Agent运行时在工具范围、人工审批与资源预算约束下完成内容理解、库内问答和组织建议。

**Larder 后端模块**

技术栈：Java21、Spring Boot4.1、Spring Security、MySQL8.4、MyBatis-Plus、Redis、RabbitMQ、Meilisearch、MinIO、Flyway、Testcontainers。按最终实际版本校正。

- **索引版本与可信检索：**针对正文更新和异步索引错版，设计ContentRevision与IndexGeneration隔离构建、manifest校验和发布指针CAS；查询以MySQL权威状态复核，__组并发/失败场景中错版返回__次。
- **异步一致性与故障恢复：**基于Outbox+RabbitMQ、Inbox持久接管和Worker Lease/fencing，处理重复投递、ack后崩溃及旧worker迟到；完成__类故障注入，重复业务发布__次，恢复P95为__s。
- **混合检索与评测：**构建关键词/向量双路召回及RRF，结合候选、排序和发布过滤归因定位检索失败；__条query的Document Recall@5为__%、Hit@5为__%，完整链路P95为__ms。

**Larder Agent / Runner 模块**

技术栈：Python3.12、FastAPI、Uvicorn、HTTP/SSE、JSONL Transcript、Checkpoint、Pydantic、实际使用的模型与embedding API。

- **运行持久化与恢复：**以JSONL记录运行事实，结合Checkpoint、产物hash和重放恢复阶段状态；覆盖__类崩溃窗口，已完成阶段复用__次，外部结果未知时自动重发__次。
- **工具执行与副作用治理：**统一schema、scope、callId、有界并行和大结果交付，写入通过绑定参数与资源版本的人工审批；__组固定调用集读取耗时变化__%，越界/无效审批拦截__/__。
- **跨会话记忆生命周期：**实现显式写入、按scope召回、替代和墓碑撤销，在每次模型调用授权前复核权威版本；__组生命周期测试中，新授权请求失效记忆注入__次。
- **长上下文与安全压缩：**围绕完整请求预算构建Key Fact Snapshot与LLM Summary，以日志提交点和Checkpoint保证可恢复切换；__篇语料token变化__%，关键事实保留率__%，压缩后续跑通过__/__。
- **Benchmark与质量评测：**建立八类业务任务、独立Verifier与模块消融，通过统一Trace比较质量、工具开销、usage和耗时；任务通过率__%，单任务token中位数__，形成逐样本可回查报告。

“零重复”只能表述在明确测试集合中观察到的业务效果，不能延伸成供应商绝对不重复收费。性能负收益也应如实呈现或换一个有证据的成果，不挑最好一次伪装稳定水平。
