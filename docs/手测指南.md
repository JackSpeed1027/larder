# Larder 手测指南（测试数据 + 方法）

> 目的：让你（或下一个窗口）能按步骤亲手复现关键行为，知道用什么数据、看哪里、期望是什么。
> 所有数据都是**本地测试数据**，不是用户真实资料。

## 0. 启动

```powershell
cd D:\Work\Project\larder
.\scripts\dev\up.ps1 -Dev          # 起 mysql/rabbitmq/minio/api/web（8080）
pnpm --dir frontend dev            # 可选：看 UI（5173）
```

账号：`admin` / `.env` 的 `LARDER_ADMIN_PASSWORD`；内部回传令牌：`LARDER_INTERNAL_TOKEN`。

## 1. 收录幂等（S01）

| 测试数据 | 值 |
|---|---|
| URL 模板 | `https://example.com/manual/{时间戳}` |
| 首次幂等键 | `manual-{时间戳}-01` |
| 第二次（同 body 同 key） | 同键同 body |
| 第三次（不同 body 同 key） | 同键，URL 换成 `/manual-other/{时间戳}` |

方法：`docs/api.http` 依次执行 ① 拿 CSRF ② 登录 ④ 收录（改 URL/键）再重复一次、再换 body 一次。

期望：

- 首次 **202** + `data.itemId`/`data.jobId`；
- 同 key 同 body → **200**，`data.itemId` 与首次相同；
- 同 key 不同 body → **409**，`code=IDEMPOTENCY_PAYLOAD_MISMATCH`。

看数据库：

```sql
select request_key,state,response_status,left(response_json,80) from idempotency_request order by created_at desc limit 5;
select id,kind,title,current_revision_id from item order by created_at desc limit 5;
```

## 2. 同 key 并发（S01 并发唯一）

一键脚本：`scripts/dev/verify-content.ps1` 里“同 key 并发”检查自动做：

- 8 个并发请求，同一 `Idempotency-Key`、同一 body、同一 URL；
- 期望 `202×1 + 200×7`，且 8 个响应的 `itemId` 全相同；
- 期望 DB 中该 item 只有 1 行。

手搓：用 `curl` 的 `--parallel` 或 Postman Runner 发 8 次同键同 body；
查 `select count(*) from item where id='itm_...'` 应为 1。

## 3. 抓取/发布（V02-T03）

| 测试数据 | 值 |
|---|---|
| 条目 | `POST /api/items`（WEB，URL 任意 example.com） |
| runId | `run_manual_{时间戳}`（SQL 写入 job.run_id） |
| 正文 | 任意中文文本，`contentSha256=sha256(utf8(text))` |
| 内部令牌头 | `X-Internal-Token: $LARDER_INTERNAL_TOKEN` |

期望：

- 回传 **200** + `revisionId`；`item.current_revision_id` 指向它；job → `SUCCEEDED`；
- 再回传一次 → **200** + `dedupe=REPLAYED`，revision 仍 1 条；
- 把 job `processing_epoch` 改成 1 后再回传 epoch=0 → **409 EPOCH_SUPERSEDED**，不写 revision。

一键：`scripts/dev/verify-publication.ps1`（会自动建数据）。

## 4. 阅读/笔记/标签（V02-T04）

- 打开 `/reader?itemId=itm_...&revisionId=rev_...`：正文应等于回传的 text，sha 前缀一致；
- 写笔记：`POST /api/items/{itemId}/notes`，`markdown` 空 → 400；
- 标签：`POST /api/tags` 同名两次 → 第二次返回同一 tag id；`GET /api/items?tag={tagId}` 只返回该条。

一键：`scripts/dev/verify-organize.ps1`。

## 5. 任务中心（V03-T04）

- `GET /api/jobs?itemId=itm_...` 能看到 job；
- `POST /api/jobs/{jobId}/cancel` → `cancelRequestedAt` 非空；再回传发布 → **409 CANCELLED_CONFLICT**；
- `POST /api/jobs/{jobId}/retry` 只对 FAILED/CANCELLED 有效，否则 **409 RETRY_NOT_ALLOWED**。

一键：`scripts/dev/verify-control.ps1`。

## 6. 测试数据清理（只清测试数据）

```sql
-- 先核对再删；不要动非测试 owner 的数据
delete from note where item_id in (select id from item where title like 'https://example.com/%');
delete from item_tag where item_id in (select id from item where title like 'https://example.com/%');
delete from outbox where job_id in (select id from job where item_id in (select id from item where title like 'https://example.com/%'));
delete from job where item_id in (select id from item where title like 'https://example.com/%');
delete from item where title like 'https://example.com/%';
```

（生产/真实数据禁止用 `delete`；本项目当前只有本地测试库。）
