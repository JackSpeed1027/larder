# 01 产品功能与边界

## 1. 产品定位与设计标准

个人自托管内容库，面向整理技术资料、回查证据和复习知识的人。核心流程：收录→抽取→版本化阅读/检索→组织/笔记→卡片复习。Agent对库内内容做检索、阅读、比较和建议写入，不替用户公开发布内容。

核心标准：AI关闭仍然好用；失败不丢原始输入；每个摘要、卡片、回答可指向具体内容版本；用户可以纠正、撤销和导出。引用能定位是必要条件，不是语义正确的充分条件。

产品不声称没有竞品。差异化假设是“原文可回查的学习流程+可观察、可恢复的内容Agent”。是否好用需要作者真实连续使用验证。

## 2. 三个端到端用户故事

1. 保存公众号或技术网页：链接立即入库，抓不到时保留链接并提示粘贴；抓到后可读可搜，摘要失败不阻断正文。
2. 回查技术结论：搜索或问答找到具体段落，引用打开指定版本；正文更新期间旧发布索引继续可用并注明旧版本，不能跳到内容不同的新正文。
3. 学习一段材料：手动或AI生成卡片，确认后进入复习；先回忆、展开答案，再评分。重复评分不重复推进；过时来源可标注、暂停、重新制卡，旧历史仍保留。

F11/F12/F13提供多来源业务输入，保留转写方向，但不自动下载第三方视频的音视频文件。平台公开字幕适配需单独验证；无可用字幕时允许用户提供文本/合法音频，不以评论摘要冒充视频内容。

四种卡型共用card/anchor/review模型。首个学习切片先完成问答卡，其余三型仍在V10工作包中；若延期必须明确报告，不得自行把它们永久删除。

## 4. 功能状态与用户提示

界面分别展示保存、正文、索引、AI状态，不能只用一个READY吞掉所有情况。

| 场景 | 用户看到的状态 |
|---|---|
| 无模型Key | “AI未启用”；全文、笔记、手动卡正常 |
| 正文成功、摘要失败 | “正文已保存；摘要失败，可重试” |
| 新正文正在建立索引 | 阅读默认新版；搜索仍使用已发布旧版并显示“索引更新中，结果基于r1” |
| 确认有费用但响应未知 | “调用结果待核对；再次调用可能再次计费” |
| 搜索服务故障 | “全文搜索暂不可用，当前仅匹配标题/标签” |
| 记忆撤销 | 后续新授权模型请求不包含该记忆；已发请求不能从供应商撤回 |
| 内容软删除 | 列表/搜索/Agent工具隐藏，复习暂停，历史与数据仍保留 |

不展示没有统计依据的“预计8秒”。先展示已用时、当前阶段和可执行操作；收集足够样本后再按类型给明确标为估计的范围。

## 5. 前端页面、状态与实现约束

| 路由 | 内容 |
|---|---|
| `/login` | 管理员登录、CSRF、错误和节流提示 |
| `/library` | 快速收录、列表、筛选、批量操作、任务状态 |
| `/items/:id` | 版本阅读、章节/锚点、摘要、笔记、建议、处理记录 |
| `/search` | keyword/hybrid切换、过滤、高亮、来源版本与降级状态 |
| `/assistant` | 库内问答、工具可见结果、审批、记忆提示和引用 |
| `/review` | 卡片、展开答案、评分、到期队列、暂停 |
| `/settings` | 模型、预算、记忆管理、时区、诊断、导出与恢复说明 |

React19/Vite/TS；服务端状态归TanStack Query，Zustand仅放UI偏好和未保存交互状态。不要把item再复制到全局store。契约生成类型，避免手工维护三份同名DTO。

同源Cookie session可使用EventSource；SSE仅展示进度和结果，刷新后以GET快照纠正。所有页面有加载/空/错误/权限失效状态。Markdown消毒，禁执行原HTML脚本；默认不自动请求远端图片。键盘可达、焦点可见、按钮禁用原因明确；视觉token集中管理，不先做动画和大盘。

## 6. 关键产品决定及代价

- 单管理员、单实例个人库，数据仍带owner_id。保留授权边界，不做成员协作，减少管理UI。
- 摘要作为AI衍生内容可直接显示；标签、卡片、集合、记忆等用户数据变更必须确认，避免审批所有只读输出。
- 旧版本为引用保留，不按“只留三版”自动删除。代价是磁盘增长，提供占用报告和明确清理预览。
- SimHash/embedding用于相似建议，不能把近似相等当成可自动丢弃用户内容的理由。
- 可选远程模型和转写会发送内容到供应商；用户启用时展示数据范围。自托管不等于所有请求始终离线。

## 7. 不做什么

不做桌面安装包、移动App、社交、推荐流、视频下载分发、登录墙绕过、自动对外发布、多租户计费、通用任意工具平台、Anki双向同步。浏览器插件和OCR是后续扩展。技术主线完整保留，以上产品边界不能被模型自行扩大。
