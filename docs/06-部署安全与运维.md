# 06 部署、安全与运维

## 1. 环境与版本冻结

保留Java21、Boot4.1、MySQL8.4、Python3.12、React19和既定中间件。精确补丁、镜像digest和依赖兼容由V01-T01验证，当前不提供未经拉取验证的假digest或“最新版安全”结论。

| 组件 | 锁定与验证 |
|---|---|
| Java/Boot/MyBatis/Flyway | Java21，Boot4.1 BOM与对应starter（Flyway 用 starter-flyway）；真实MySQL迁移与CRUD集成用例；禁止手工混配Framework/Security旧版本 |
| MySQL8.4 | 固定补丁镜像；时区UTC、utf8mb4、实际索引长度/事务语义测试 |
| RabbitMQ4版本线 | 固定受评估版本；confirm/return/manual ack/DLQ测试；单节点不宣称HA |
| Redis | 固定版本与许可记录；Lua限流/超时降级测试；缓存不得承载唯一业务事实 |
| Meilisearch1版本线 | 验证user-provided vectors、向量维度、异步tasks和检索参数；固定版本再生成配置 |
| MinIO | 保留S3对象存储主线；固定可复现构建/镜像及hash，不使用latest；兼容SDK通过读写/分片/校验/备份测试 |
| Python生态 | Python3.12、uv.lock、Pydantic schema和解析/转写库；许可与资源边界核对 |
| 前端 | Node/pnpm/Vite精确兼容组合、lockfile；React19/Tailwind4构建及浏览器E2E |

本次核查发现[MinIO官方仓库](https://github.com/minio/minio)已标为归档，且官方二进制/镜像渠道均已关闭；按用户决定继续用 MinIO，改为源码固定 tag 构建并锁 commit+sha256（ADR-0003）。不能假定今后仍有社区安全更新。API依赖S3适配接口而非MinIO专有行为。V01记录维护状态和镜像获取方式，V12重新检查发布风险。若维护/许可/漏洞使所选构建不适合公开部署，提交ADR选择受维护的S3兼容服务；替换实现不删除对象存储能力，也不在未说明的情况下悄悄换技术栈。

[Boot4.1系统要求](https://docs.spring.io/spring-boot/4.1/system-requirements.html)可核对Java兼容，但文档可访问不等于当前仍有OSS维护。V01同时核对支持期；升级已在 V01-T01 R2 执行（ADR-0002）；后续若再升级仍须先给兼容实验与具体理由，不能因存在新版本就重写全栈。

## 2. 部署拓扑与资源

| 常驻服务 | 容器内部端口 | 持久内容 | 对外暴露 |
|---|---:|---|---|
| web | 80 | 构建静态资源 | 仅127.0.0.1:8080 |
| api | 8080 | 无业务本地文件；临时上传缓冲受限 | 无，Web反代/api |
| runner | 8000 | journal、checkpoint、暂存/待接收产物 | 无 |
| mysql | 3306 | 全部权威业务数据 | 无 |
| redis | 6379 | 派生缓存/短期计数 | 无 |
| rabbitmq | 5672/15672 | 消息、definitions和诊断 | 无；管理台开发override限loopback |
| meili | 7700 | 内容/记忆派生索引 | 无 |
| minio | 9000/9001 | 原文件、正文、转录、产物 | 无；管理台开发override限loopback |

初始化bucket、运行迁移可以是短命init服务，不算新增常驻微服务。只有一个发布部署组合，不同时维护“纯DB精简版”。应用开发用Vite5173代理API，开发override与发布配置分开，不能把localhost地址写进容器内部连接。

资源先用Docker可分配8GiB内存、20GiB空闲磁盘作为验证环境，**不是已测最低配置**。每个服务有可解释的CPU/内存/连接/并发上限；原文件增长、journal和备份占用另计。ASR采用用户明确选择的本地小模型或远端服务，默认不开GPU依赖，必须报告具体硬件上的耗时和失败分布。

主路径支持Linux容器及Windows Docker Desktop/WSL2，ARM64需单独验证后才标支持。用户运行发布镜像只需Docker/Compose；开发者才需要本地JDK/Node/Python工具链。

## 3. 配置与秘密

环境变量前缀统一LARDER_，字段分app/db/redis/rabbit/search/storage/runner/model。`.env.example`只写占位和生成说明；不得内置公共管理员密码或把guest/guest当远程MQ方案。实际`.env`、Key、Cookie、数据卷不入Git。

API只拿应用级MySQL账号、有限S3 bucket权限、特定Rabbit exchange/queue权限和服务器搜索key。MinIO root仅用于初始化/维护，Runner无对象存储root、DB或MQ凭据。模型Key仅供Runner；Java只保存provider配置标识和脱敏显示。后台模型endpoint由管理员配置，用户普通输入不能修改。

同源Cookie session：HttpOnly、SameSite、CSRF、Origin/Host检查；loopback HTTP可不设Secure，远程部署必须TLS与Secure。未经配置不得自动监听0.0.0.0。actuator仅开放必要health，详细metrics/配置不经公共代理泄露。

外网抓取、Java内部工具、模型供应商分别用独立HTTP客户端和地址策略。原文和上传内容不可信，SSRF实际连接校验、响应体解压限额、PDF隔离、Markdown消毒、禁止远端图片自动加载共同实施。依据[OWASP SSRF防护](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。

## 4. 故障降级矩阵

| 故障 | 可以继续 | 停止/告知 |
|---|---|---|
| 模型或embedding不可用 | 阅读、关键词、手动组织/卡片/复习 | AI失败或关键词降级，已发送未知请求另行标记 |
| Runner不可用 | 原库阅读和已建索引查询 | 新处理job保留，恢复后对账，不能显示已处理 |
| Rabbit不可用 | 接受预算/容量内的持久收录，已有库可读 | Outbox积压；新任务不走临时同步旁路 |
| Redis不可用 | 默认单实例保守本地限流+DB预算，跳过向量缓存 | 明确降级，不能绕过额度或权限 |
| Meili不可用 | 正文、笔记、复习，标题/标签限量搜索 | 全文/语义不可用提示 |
| MinIO不可用 | 元信息与可验证的DB文本块可读 | 原文件下载、新产物发布暂停；不可造空文件 |
| MySQL不可用 | 静态UI和liveness | 新授权/写入/内容访问按策略失败关闭，不从缓存猜权限 |
| 磁盘满或journal损坏 | 不受影响的已存内容 | 当前run停止，保留现场，不清空历史腾空间 |

API liveness表示进程存活，readiness反映MySQL和必要配置；组件健康和业务降级独立报告。可选依赖故障不能触发整个应用无限重启。

## 5. 备份与恢复

### 5.1 备份一致性边界

V04先做最小恢复能力，V12完整复验。单用户接受维护窗口：

1. 在MySQL记录维护状态，阻止新用户写、新job和call授权；暂停Relay/消费者派发，等待在途事务和对象上传完成。
2. run在可恢复边界暂停；未知外部调用保留UNKNOWN。停止Runner写journal并确认fsync/段完整，备份期间API/后台不能继续修改业务快照。
3. 导出MySQL一致性快照、所有被引用MinIO对象/版本与SHA清单、Runner完整journal/checkpoint/产物、schema/镜像/索引profile和配置标识。密钥另行安全保管，普通分享包不含秘密。
4. 备份Rabbit definitions及DLQ诊断。业务通知可由DB job/outbox重建，不要求把MQ瞬间顺序当业务事实；Redis缓存、Meili索引可重建，但配置/模型profile必须保存。
5. 验证文件hash和数据库引用完整性，生成backup manifest后解除维护。写到带唯一ID的新目录，不覆盖上次成功备份。备份失败保留原库和已产生文件，给诊断。

只拷贝正在变化的数据卷不算一致备份；只导出MySQL但没有对应对象和运行日志也不完整。备份包含私密正文和可能的session数据，不自动上传或分享。

### 5.2 隔离恢复步骤

恢复只能到新目录、新卷、新Compose project。先校验manifest/schema，再导入MySQL、对象和journal；初始化空MQ/Redis及索引，按DB非终态job产生新的wake通知，Runner按原runId重放。旧实例、原备份和原队列不修改。

恢复时默认关闭模型调用和自动写执行，重新发放服务凭据、失效旧session/capability，并将未执行审批标为需要复核且留审计；UNKNOWN不可自动重发。已完成action按actionId保留幂等结果。index generation从权威manifest重建，完整验证后再启用服务。

抽查正文、原文件、旧版引用、记忆墓碑、四卡型、复习状态、已完成/未知run和审批结果。RPO/RTO填实测，恢复失败不切换端口或工作目录。正式启用新实例由用户明确决定，不自动替换旧数据。

## 6. 升级、保留与数据清理

升级前有有效备份和版本清单；迁移先在备份恢复副本验证。已应用Flyway迁移只增不改，优先兼容性扩展；应用回滚前检查schema兼容，不以反向删表自动回滚。

用户原件、内容版本、journal、记忆撤销记录、复习日志、备份默认保留。空间治理先报告准确对象/路径、引用关系、占用和影响；物理清除需针对范围的明确授权并先备份，用户明确无需备份时遵从。派生索引可重建不意味着可以顺便清空同卷上的原始数据。

不使用清卷、全库reset或覆盖历史来排查“读不到旧内容”。本项目约束同样适用于脚本和自动化任务。

## 7. 可观测、doctor与发布条件

结构化日志关联traceId/itemId/jobId/runId/callId/actionId，保留错误分类和耗时，不记录秘密/完整私人正文/隐藏思维。指标至少包括outbox_age、confirm失败、DLQ、lease_reclaimed、stale_commit_rejected、index_lag、candidate/filter miss、memory_stale_rejected、context_compactions、unknown_calls、usage与磁盘。

doctor只读检查：版本、端口、配置缺项、连接权限、迁移版本、S3读写测试目录、协议兼容、模型启用状态和磁盘；S3写探针只能在明确专用测试前缀内，默认只读不擅自创建用户对象。诊断输出脱敏。

发布必须有：干净实例启动记录、AI关闭端到端、核心故障矩阵、真实模型小额演示、恢复报告、许可证/依赖说明、已知维护风险、README截图与支持范围。未完成记录明确写“未验证”，不把18周排期当完成证据。

## 8. 不做什么

不承诺单节点高可用、不默认开放管理台、不自动获取用户Key、不无界转写、不删除原始数据、不把归档组件当作持续受支持产品、不擅自替用户发布或切换正式实例。
